3. How Geographic Screening Works

Scrolls for Sol: Enoch performs automated geographic screening at application launch to determine the user's country of location. The screening uses multiple signals, evaluated in the following priority order:

  1. SIM Operator Country Code (Highest Priority) — The mobile country code (MCC) registered to the device's SIM card is used to determine the country associated with the user's mobile network operator. This is the most reliable indicator as it reflects the telecommunications registration of the device.
  2. Network Operator Country Code — The country code of the network to which the device is currently connected. This may differ from the SIM operator when roaming internationally.
  3. Device Locale — The country/region setting configured on the device by the user. While user-configurable, this provides a supplementary geographic signal.

The application requests no location permission and performs no location lookups; only the three device-country signals above are read, and nothing leaves the device.

Screening Decision: If any of the above signals indicates that the user is located in a restricted jurisdiction, access to Scrolls for Sol: Enoch will be blocked. The application applies a conservative approach — a match on any single signal is sufficient to trigger the restriction.

4. Privacy-Preserving Design

Your privacy is protected. All geographic screening is performed entirely on-device. No location data, country codes, or screening results are ever transmitted to any external server.

Scrolls for Sol: Enoch's sanctions compliance screening is designed with privacy as a core principle:

  • On-device processing only — All country determination logic runs locally on the Seeker device. No data leaves the device during the screening process.
  • No data transmission — SIM operator codes, network codes, device locale, and location data are read by the application but are never sent to any server, API, analytics service, or third party.
  • No data storage — Geographic screening data is processed in memory during application launch and is not persisted to disk, databases, or shared preferences.
  • Coarse location only — If location permission is granted, the application requests only coarse (approximate) location, which provides city-level accuracy at most. Fine (GPS-precise) location is never requested or used.
  • Immediate disposal — Any location data obtained through the Geocoder reverse lookup is used solely for country-level determination and is immediately discarded after the check is complete.
  • No tracking — The application does not track, log, or record user locations over time. Each screening check is independent and stateless.
